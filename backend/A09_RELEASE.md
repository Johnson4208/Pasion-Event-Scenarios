# A09 time-aware market probability validation

Extends existing F05 frozen model registry. Training/calibration boundary purges h-session labels, calibrator is fit only on later past held-out OOS origins, and evaluation uses untouched origins after actual freeze time. Existing expanding walk-forward diagnostic folds retain horizon purging; they do not tune the frozen champion. Feature function slices only historical bars known at origin. Revised training snapshots require a new model ID.

Freezes now require both return classes in training/calibration and record feature-policy version/names/history, model artifact hash, calibrator hash and validation-policy version. Each immutable evaluation has its own ID, feature/prediction snapshot hashes, train/calibration/test coverage, walk-forward evidence and two temporal stability windows. Current A09 gate requires positive Brier skill against frozen training baseline and both classes in each test half, as well as existing total sample>=80, ECE<=.1, positive total skill, both test classes and expiry rules. Bad skill, incomplete calibration or unstable windows suppress p_up/p_down and directional advice. Old evaluated reports require revalidation under a09-v1; old probabilities do not silently inherit new acceptance.

Return label remains Close[t+h]/Close[t]-1>0, with nonpositive-return complement. UP>=.58 and DOWN<=.42 only after reliability gate. Absolute distance from .5 is not confidence. Future test labels can overlap within the evaluation cohort, so independent_test_sample_count separately counts h-spaced origins and dependency caveat is explicit. No independent-trial significance or confidence interval is claimed. Frozen feature/model/calibrator artifacts are not refit by evaluation. No company cash-flow forecast, scenario judgment, accounting health or Kelly edge is substituted for return probability.

This implementation uses the existing reviewed fixed logistic/Platt baseline with return1/5, SMA20 gap and vol20 features. The legacy random-forest ensemble and longer feature list are not claimed implemented or validated; they require separate versioned candidates and out-of-time evaluation before admission. Stability thresholds are versioned engineering release gates, not proof of investment profitability or future calibration. No real model is seeded. The service stays optional and unavailable until provider-backed samples meet gates.

Stock horizon cards retain layout and expose policy/stability, sample dependence, evaluation IDs, artifact hashes and feature provenance in details. Numeric probability still remains server-gated and client-expiry checked. New tests perturb future bars without changing historical features, reject later-known revisions in a feature window, test baseline skill/class coverage and deterministic hashes. Existing F05 tests cover insufficient cohort, failed skill, frozen-history changes and complementary probability/expiry.

Validation: all 7 focused stock-model/API tests and 3 A09 tests passed. Both F05 browser checks passed; production build passed with the existing bundle warning. Full backend suite was not repeated. Project restarted with A09 active. No real statistical/economic performance certification follows from synthetic fixtures; live probabilities remain unavailable without reviewed provider/model evidence.
