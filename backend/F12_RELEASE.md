# F12 staged financial document review

Existing admin upload/library/retry/download/QA retained. Financial observation review is separate from generic extraction. GET admin `/api/admin/finance/observations?document_id=...` provides extracted sections, original SHA256, registered taxonomy and XBRL/iXBRL adapter contract. No production XBRL parser is claimed; reviewed sidecars/PDF/OCR observations are supported first.

POST `/api/admin/finance/stages` takes document_id and F03-style payload with one report, calendar and facts. Exact section/page and either zero-based table row/column or verbatim text excerpt are required, plus ownership and interpretation rationale. IDs/hash/parser are server-generated. Raw observation/excerpt, row/column context and proposed numeric interpretation are stored separately, immutable. Validation uses the canonical F03 writer inside a rolled-back savepoint: staged facts never enter research.

POST `/api/admin/finance/stages/decide` requires stage_id, ACCEPT/REJECT, note and explicit acknowledgment of discrepancies when warnings exist. Acceptance atomically publishes facts and immutable citation snapshots in finance.sqlite3; decision is final. Corrections require a new stage/revision, optional parent_id. Hash is rechecked at acceptance. Known time is acceptance time or later source availability. Existing direct F03 reviewed-facts endpoint remains for reviewed integrations; it does not create a staged UI record.

Assets/liabilities/equity identity checks flag missing/incompatible components and decimal discrepancies but never repair extracted numbers. UI maps one observation at a time; multi-fact sidecars may be staged by API. Stock facts require INSTANT periods; unpaginated DOCX sections use an explicit section locator, never a fabricated page. Accepted metric evidence exposes only reviewed bounded excerpts and hash/coordinates, never original file bytes, internal paths or admin reviewer identities. Referenced financial documents cannot be deleted. Existing optional document AI is not used by financial ingestion or acceptance.

Admin UI provides issuer/calendar/context, source previews, mapping, acceptance/rejection and immutable history. Exact accepted excerpts open in the existing company metric drawer. F03 and F04 consume accepted canonical fact IDs. XBRL adapter contract requires namespace/concept/context/entity/period/unit/decimals/dimensions/locator and must emit the same reviewed stages. Automatic taxonomy disambiguation, production XBRL ingestion and automated audit certification are not implemented.

Tests verify unpublished stages, exact excerpts, acceptance/rejection, bad coordinates and immutable decisions, plus existing F03 semantic calculations. Production identity/storage review from F01 remains required.

Validation: backend regression run passed 179 tests; final staging suite passed 12 checks (including inherited finance-core tests and discrepancy preservation), existing focused finance API/core suite passed, production build passed, and F03 metric-drawer browser checks passed. No dedicated end-to-end browser test of the new admin mapping form was performed; that workflow has backend verification and compilation coverage. Local F12/F13 API routes activated after restart. No real issuer document was accepted during this task.
